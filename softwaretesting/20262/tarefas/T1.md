1. Cadastre uma tarefa (issue) para você com o título **“Tarefa 01 \- Teste de Unidade, Integração, Cobertura e CI \<nomedodiscente\>”** no repositório da disciplina.
   1. Coloque o link da sua tarefa (issue) no arquivo [https://github.com/tacianosilva/bsi-tasks/blob/main/softwaretesting/20262/README.md](https://github.com/tacianosilva/bsi-tasks/blob/main/softwaretesting/20262/README.md)
2. Faça o **fork** do repositório [BSI-TASKS](https://github.com/tacianosilva/bsi-tasks).
3. Faça **um clone do seu fork**:
   *git clone https://github.com/\<username\>/bsi-tasks.git*
4. Crie um diretório com seu ***nome de usuário do github*** dentro do diretório *softwaretesting/20262/tarefas.*
5. Crie um arquivo **README.md** para concentrar os links e páginas que for criar.
6. Crie um arquivo chamado **tarefa01.md** no seu diretório e coloque o link para ele no README.md da questão anterior.
7. Coloque na página **tarefa01.md** o título da página **“Tarefa 01 \- Teste de Unidade, Integração, Cobertura e CI”**, e abaixo do título coloque seu **nome, usuário github e e-mail.** Coloque também o **link para o repositório do seu projeto** (Questão 10).
8. Para resolver a questão 9, crie uma branch da tarefa (task/issueID) e para cada item que você faça um commit. Na mensagem de commit sempre acrescente o ID da issue criada na questão 1. Ao final da atividade faça um **Pull** para seu repositório da disciplina. Depois crie um **Pull Request** da branch do seu fork para a branch main repositório da disciplina.
9. Crie uma seção na página **tarefa01.md** com as seguintes informações:
   1. Pesquise e fale um pouco sobre Testes de Software com foco em **Testes de Unidade**. Coloque um pequeno resumo.
   2. Defina uma **linguagem de programação, uma stack** para desenvolver o projeto da disciplina.
   3. Busque um **framework de Testes de Unidade** para a linguagem escolhida e fale um pouco sobre o **framework** escolhido. Coloque um pequeno resumo sobre o framework de testes e links para ele.
   4. Fale um pouco da IDE que você utiliza. Fale sobre as **ferramentas de debug** que ela tem integrada.
   5. Busque pelo menos um Tutorial para fazer um CRUD na tecnologia escolhida e que mostre a construção de Testes de Software. Apresente o link e descreva em poucas palavras o conteúdo do tutorial.
   6. Pesquise sobre **Mocks Objects** em Testes de Unidade e faça um pequeno resumo.
10. Criar repositório para seu projeto.
    1. Crie um repositório no seu usuário e implemente um CRUD (UserStory). Deve ter pelo menos 4 operações: inserir, atualizar, deletar e consultar. Pode adicionar outras operações.
    2. Coloque o link do seu repositório no arquivo [https://github.com/tacianosilva/bsi-tasks/blob/main/softwaretesting/20262/README.md](https://github.com/tacianosilva/bsi-tasks/blob/main/softwaretesting/20262/README.md)
    3. Adicione pelo menos um Tutorial para fazer um CRUD na tecnologia escolhida e que mostre a construção de Testes de Software. Apresente o link e descreva em poucas palavras o conteúdo do tutorial no README do seu projeto.
    4. Implemente pelo menos um **Teste de Unidade** para cada operação do CRUD. Geralmente Testes de Unidade atuam em funcionalidades isoladas e usam **Mock Objects**. Explique em resumo como foi a experiência de implementar os testes. Coloque o link para o arquivo de teste no repositório do projeto.
    5. Implemente pelo menos um **Teste de Integração** no seu projeto e explique a diferença entre Teste de Unidade e Teste de Integração.
    6. Execute a **ferramenta de testes** escolhida para o seu projeto (ex.: **Jest** no Node, **unittest** ou **pytest** no Python, ou a ferramenta que você escolher). Apresente a saída da execução do comando de teste.
    7. Calcule a **cobertura de código** e **gere o relatório** da ferramenta de cobertura (formato compatível com o SonarQube). Apresente o relatório/evidência da cobertura obtida.
    8. Crie um **script de CI usando o GitHub Actions** no repositório do seu projeto com, no mínimo, os passos de instalação das dependências, execução dos testes e cálculo/geração da cobertura (step de cobertura).
    9. **(Extra — não compõe a nota da T1)** Crie o arquivo `sonar-project.properties` e configure o **GitHub Actions** com um passo adicional do **SonarQube Scanner** apontando para o servidor do LABENS ([https://labens.dct.ufrn.br/sonarqube/](https://labens.dct.ufrn.br/sonarqube/)), utilizando um token configurado como secret. Apresente o link do projeto analisado no SonarQube. Consulte o guia de configuração: [https://github.com/tacianosilva/eng-software-2/blob/main/docs/sonarqube/config.md](https://github.com/tacianosilva/eng-software-2/blob/main/docs/sonarqube/config.md)
11. Para resolver a questão 10, crie uma tarefa (issue) e uma branch da tarefa (task/issueID) no repositório do seu projeto e para cada item que você faça um commit. Na mensagem de commit sempre acrescente o ID da issue criada na questão 1. Ao final da atividade faça um **Pull Request** do branch da tarefa para a branch **main**.

Lembre-se das boas práticas do Git:

1. **atualizar seu fork** a partir do original com **pull request** antes de começar a desenvolver
2. faça **um clone do seu fork**
3. fazer git pull para atualizar sua pasta de trabalho: **git pull**
4. fazer commits pequenos e sempre colocar uma mensagem relevante e ao final da mensagem identifique a issue com **\#\<id\_issue\>**
5. enviar suas modificações para seu repositório remoto: **git push**
6. enviar um **pull request** com suas contribuições.
