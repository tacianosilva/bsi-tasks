**Tarefa 03 \- Implementação do User Story da Iteração 2 e Atuação como QA**

Para responder às questões abaixo você deve utilizar o seu **fork** do repositório **bsi-tasks** no GitHub: [https://github.com/tacianosilva/bsi-tasks](https://github.com/tacianosilva/bsi-tasks).

Nesta atividade prática individual, consolidamos o fluxo de desenvolvimento com garantia de qualidade (QA) contínua para a Iteração 2 do projeto, onde cada discente atua tanto como **Desenvolvedor** quanto como **QA Engineer / Testador** para um colega de equipe.

---

### Instruções no Repositório `bsi-tasks`

1. Cadastre uma tarefa (issue) para você com o título **“Tarefa 03 \- Implementação do User Story da Iteração 2 \<nomedodiscente\>”** no repositório da disciplina (`tacianosilva/bsi-tasks`).
   1. Coloque o link da sua tarefa (issue) no arquivo [https://github.com/tacianosilva/bsi-tasks/blob/main/softwaretesting/20262/README.md](https://github.com/tacianosilva/bsi-tasks/blob/main/softwaretesting/20262/README.md).
2. No seu clone local do fork do `bsi-tasks`, atualize sua branch `main` com o repositório original (*upstream/origin*).
3. Crie uma branch específica para a tarefa: `git checkout -b task/issueID` (substituindo `issueID` pelo número da sua issue cadastrada).
4. Dentro do diretório `softwaretesting/20262/tarefas/<username>/`, crie o arquivo **`tarefa03.md`** e adicione o link para ele no seu **`README.md`**.
5. No arquivo **`tarefa03.md`**, inclua:
   * **Título:** “Tarefa 03 \- Implementação do User Story da Iteração 2 e Atuação como QA”;
   * **Identificação:** Seu nome completo, usuário GitHub e e-mail;
   * **Links de Entrega:** Link do Pull Request no repositório do seu projeto de grupo e link para o Relatório de Testes de Aceitação (QA) gerado.

---

### Atividades Práticas e Fluxo de Desenvolvimento

6. **Especificação do User Story e Testes de Aceitação (Papel de Analista/Dev):**
   * Descreva detalhadamente a especificação do seu User Story alocado na Iteração 2 no documento de User Stories do repositório do projeto.
   * A especificação deve incluir formalmente os cenários de **Testes de Aceitação (Testes de Sistema)** escritos na sintaxe **BDD / Gherkin** (`Dado que... Quando... Então...`).
7. **Implementação da Funcionalidade e Testes Automatizados (Papel de Desenvolvedor):**
   * Implemente o código da funcionalidade correspondente ao seu User Story da Iteração 2 na branch da sua issue no repositório do projeto.
   * Implemente a suíte de **Testes de Unidade** com Mock Objects isolando dependências externas.
   * Implemente pelo menos um **Teste de Integração** funcional validando a integração de módulos ou persistência.
   * Execute as ferramentas de teste e verifique a cobertura obtida.
   * Verifique os resultados da análise estática no **SonarQube do LABENS** e **resolva os problemas apontados** (code smells, bugs e vulnerabilidades).
8. **Atuação como QA Engineer de um Colega:**
   * Obtenha a branch de implementação do User Story da Iteração 2 de outro colega da sua equipe.
   * Execute os cenários de **Testes de Aceitação (Testes de Sistema)** descritos na especificação do colega para a Iteração 2.
   * Elabore o **Relatório de Testes de Aceitação** em formato Markdown no repositório do grupo documentando:
     * Casos de testes executados e seus resultados (Passou / Falhou);
     * Evidências e passos para reprodução de eventuais bugs encontrados;
     * Apontamentos de melhorias de negócio, inconsistências ou ajustes nos fluxos do User Story.
9. **Pull Request no Repositório do Projeto:**
   * Abra um Pull Request (PR) no repositório do seu projeto contendo sua implementação, testes automatizados e o link do relatório de QA que você realizou para o colega.
10. **Envio da Tarefa no `bsi-tasks`:**
    * Na página `tarefa03.md`, detalhe o resumo de suas implementações, testes, prints/evidências da análise do SonarQube e link do Relatório de QA.
    * Faça commits pequenos utilizando Conventional Commits referenciando a issue (`#<id_issue>`).
    * Faça push da branch `task/issueID` para o seu fork e abra o **Pull Request** para a branch `main` do `tacianosilva/bsi-tasks`.
