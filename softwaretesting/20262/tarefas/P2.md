**Projeto 02 \- Planos de Teste e Integração Contínua com SonarQube (Grupo)**

Para entregar as atividades de projeto, a equipe deve utilizar o repositório público oficial do projeto no GitHub e atualizar os links correspondentes neste repositório.

Nesta etapa, o foco é a formalização da estratégia de garantia de qualidade (QA) para o sistema e a configuração de automação contínua de testes e inspeção estática no SonarQube do LABENS.

---

### Atividades Obrigatórias

1. **Plano de Teste Geral (PTG):**
   * Elaborar o Documento de Plano de Teste Geral na pasta `docs/` do repositório ([Modelo YP-Agentic](https://github.com/tacianosilva/engenharia-software/blob/main/yp-agentic/templates/plano-geral-testes.md)).
   * Conter: escopo e objetivos dos testes, níveis adotados (unidade, integração, sistema), ferramentas de teste e cobertura, papéis e responsabilidades, e critérios de entrada e saída.
2. **Plano de Teste das Iterações 1 e 2 (PTI):**
   * Mapear e detalhar os casos de teste específicos planejados para cobrir os User Stories desenvolvidos nas Iterações 1 e 2 ([Modelo YP-Agentic](https://github.com/tacianosilva/engenharia-software/blob/main/yp-agentic/templates/plano-teste-iteracao.md)).
   * Cada caso de teste deve ter ID, pré-condições, passos de execução, dados de entrada e resultado esperado.
3. **Configuração do SonarQube (`sonar-project.properties`):**
   * Criar o arquivo `sonar-project.properties` na raiz do repositório do projeto.
   * Configurar: `sonar.projectKey`, `sonar.projectName`, `sonar.sources`, `sonar.tests`, relatórios de cobertura de código e exclusões pertinentes.
4. **Pipeline de Integração Contínua (CI) com GitHub Actions:**
   * Criar ou atualizar o workflow em `.github/workflows/` para rodar a cada Push ou Pull Request na branch principal (`main`).
   * Passos obrigatórios no workflow:
     1. Configuração do ambiente e instalação de dependências;
     2. Execução da suíte de testes automatizados;
     3. Geração do relatório de cobertura de testes em formato compatível com o SonarQube;
     4. Execução do SonarQube Scanner enviando as métricas com sucesso para o servidor do LABENS ([https://labens.dct.ufrn.br/sonarqube/](https://labens.dct.ufrn.br/sonarqube/)).
   * Utilizar tokens seguros via *GitHub Secrets* (`SONAR_TOKEN`, `SONAR_HOST_URL`). Consulte o [Guia de Configuração](https://github.com/tacianosilva/eng-software-2/blob/main/docs/sonarqube/config.md).
