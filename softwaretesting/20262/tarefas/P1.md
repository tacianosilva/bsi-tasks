**Projeto 01 \- Dados dos Projetos e Documentos Gerais do Projeto (Grupo)**

Para entregar as atividades de projeto, a equipe deve utilizar o repositório público oficial do projeto no GitHub e atualizar os links correspondentes neste repositório.

Nesta primeira entrega de projeto, o foco é a inicialização do repositório, levantamento de requisitos, planejamento das iterações do semestre e auditoria do estado atual dos testes no sistema.

---

### Atividades Obrigatórias

1. **Repositório do Projeto:**
   * Criar ou disponibilizar o link do repositório público no GitHub utilizado pela equipe.
   * Configurar o `.gitignore` e `README.md` com links para a documentação e membros da equipe.
2. **Documento de Visão:**
   * Criar/atualizar o Documento de Visão na pasta `docs/` do repositório em formato Markdown ([Modelo YP-Agentic](https://github.com/tacianosilva/engenharia-software/blob/main/yp-agentic/templates/doc-visao.md)).
   * Conter: descrição do problema/sistema, escopo, perfis de usuários/personas, requisitos funcionais e não funcionais, e tabela de riscos.
3. **Lista de User Stories (Product Backlog):**
   * Elaborar a lista de histórias de usuário do projeto em formato Markdown ([Modelo YP-Agentic](https://github.com/tacianosilva/engenharia-software/blob/main/yp-agentic/templates/doc-userstories.md)).
4. **Plano de Iterações Geral:**
   * Planejar as entregas em **duas iterações por unidade** (totalizando 6 iterações no semestre).
   * Alocar obrigatoriamente **pelo menos um User Story por membro por iteração** (distribuição individual clara).
5. **Relatório do Estado Atual dos Testes:**
   * Diagnosticar e documentar formalmente o estado dos testes do sistema antes da disciplina:
     * Existem testes de unidade ou de integração?
     * Qual a cobertura atual?
     * Se for um sistema legado sem testes, documentar o débito técnico identificado.
6. **Plano da Iteração 1:**
   * Documentar o planejamento detalhado da Iteração 1 (15 a 22 dias) com as tarefas distribuídas para os membros da equipe.

---

### Entrega

O representante do grupo deve cadastrar uma issue no repositório da disciplina com o título **“P1 - Dados dos Projetos e Documentos Gerais - Grupo <Nome>”** e atualizar os links em [softwaretesting/20262/README.md](../README.md):
* Link do repositório público no GitHub;
* Link do Documento de Visão;
* Link do Relatório do Estado Atual dos Testes;
* Link do Plano da Iteração 1.
